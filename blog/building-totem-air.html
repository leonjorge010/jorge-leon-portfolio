Building Totem-Air

A custom drone Remote ID monitoring system — capturing broadcasts, decoding them, and showing flights on a live operations dashboard.

Drones are required to broadcast identification and position data, but event and festival operators still need a practical way to see who’s flying, where they are, and whether a flight is authorized — especially when multiple production drones and unknown aircraft share the same airspace.

Totem-Air is the system I built for that problem. It passively captures those transmissions, decodes them using parsers I wrote for both the open Remote ID standard and DJI’s proprietary format, tags each message with position and time, and shows the results in a live dashboard built for operations teams.

The work spanned the full stack: radio behavior and antenna placement at the bottom, signal decoding and protocol work in the middle, and backend plus interface design at the top. The UI includes a live map for show operations, a registry of previously identified drones, and a flight history page that can replay a full flight and its data.

Reliable capture in a noisy RF environment meant careful antenna placement and receiver design. Supporting both the open standard and DJI’s format required separate parsers that still fed one consistent data model. The dashboard had to stay usable for ops teams in the field — live map, history replay, and drone registry — without becoming cluttered during a busy show.

During testing, Totem-Air was evaluated alongside systems used by other agencies and recognized for stronger capability at lower cost. It has run at about five shows so far, flagging dozens of unauthorized flights while helping keep authorized production drones deconflicted. Development continues toward fuller integration into festival operations.
